# HunterCueForever 1.0.0 implementation plan

User authorizes complete delivery and first public GitHub release of a Hunter rotation helper covering Beast Mastery, Marksmanship, and Survival weaving. Codex authors; Claude reviews independently read-only before implementation and again after tests on the full package. Game installation is read-only; no game screenshots authorized. No other channels are authorized or used. This file is development documentation, not a runtime asset.

## Decision

Standalone, dependency-free addon for Forever interface 16001. MaxDps was inspected only to understand its hook/API patterns; no MaxDps code is copied. Its Power helper returns infinity for secret mana, making it unsuitable as our resource model. Keeping independent state also isolates the product from official rotation/module updates. Lua implementation is original MIT code. WoWSims simulations are a development reference, not shipped dependencies.

## Product

- One next-spell icon with localized learned-rank spell names, reason text, two maintenance indicators (Hunter's Mark/Serpent Sting), separate burst suggestion, and a weaving movement advisory. No automatic casts, movement, targeting or protected button changes.
- Three selectable profiles BM/MM/SV weaving plus auto-detection via learned signature talents. Manual selection is always available. Not a universal hybrid talent optimizer.
- Three resource strategies balanced/conserve/burst, manually selected 1/3/6 target categories, burst on/off and traps opt-in. Default single-target, balanced, traps off. Manual target count avoids pulling unseen/controlled enemies based on uncertain nameplate counts.
- Hunter-only and Forever-only. Show on a living hostile non-player target. Show learned-rank ability icons only. Casting/channeling: wait, never instruct interruption of Volley or Aimed/Sniper casts.
- Draggable compact frame; saved per-character settings; slash /hcf for show/hide/lock/reset, spec, mode, targets, burst, traps, position, status diagnostics. Visible controls for routine profile/mode/target changes.
- Out-of-combat spec/spellbook rescans on login, spell changes, talent changes. Correct rank uses explicit rank-ordered spell-ID arrays intersected with learned spellbook IDs, including skipped ranks; no locale text parsing or maximum numeric-ID rule. Future ranks are not auto-discovered; unsupported new ranks require a verified data update. Reject off-spec/unlearned entries.

## State and restrictions

- Guard all addon-readable inputs with issecretvalue before comparisons, string conversion, iteration, indexing as keys, or arithmetic; pcall at API boundary. Never persist secret values. No pixel reading, hidden widget secret extraction or combat-log dependency.
- Spell readiness uses C_Spell.IsSpellUsable (usable and insufficientPower) plus GetSpellCooldown.isEnabled/isActive (documented NeverSecret fields). Cache per-spell isOnGCD ONLY inside SPELL_UPDATE_COOLDOWN; use that trusted event snapshot to distinguish GCD-only candidates from actual cooldowns. Numeric cooldowns, when readable, override a contradictory GCD classification. During GCD rank the next GCD-only candidate and show its icon with the native cooldown sweep and label 下一技能; do not keep the just-cast spell. Successful casts invalidate their shared cooldown family immediately; spell/world/spec changes invalidate the whole cache; stale snapshots expire after 2 seconds and fail closed. Test event ordering, shared cooldowns and stale-cache cases. A duration object can be passed to an owned Cooldown only for display. Unknown readiness does not count as ready.
- Spell range via IsSpellInRange; absent/secret range means unknown, not melee/far. Never equate not-near to in-range. Moving blocks cast-time spells. Unknown movement blocks cast-time recommendations conservatively.
- Scan readable HARMFUL|PLAYER aura data; if enumeration is restricted/partial, do not assert absence. Optional own cast-based timers are labelled estimates, never exact aura detection. For target debuffs, only associate SENT->SUCCEEDED with the same readable castGUID and target generation/GUID after the readable SENT target name matches the current target name, excluding readable duplicate-name focus/mouseover ambiguity; estimates remain uncertain because names are not GUIDs and casts can miss/resist; a target switch, world transition, death, reload or missing association invalidates inference. No repeated mark/sting priority lock when aura and cast evidence are unknown; maintenance indicators say unknown and main damage logic continues.
- Mana and regen automatic budgeting only when numeric values are readable. Otherwise show manual-mode status and continue selected strategy; no infinity or fake low-mana percentage. Conserve mode itself works without exact resource reads. Accurate mana display may use sanctioned display sinks but never re-read displayed values for decisions.
- Mana reserve when readable uses actual learned-rank cost, current mana, current casting regen and a short explicit horizon. Never assumes boss death time. No promise of exact mana optimization on restricted clients.
- Player cast events for hunter spell IDs and Auto Shot are used only when readable. Infer BM two-Hawks/one-Arcane sequence only from confirmed successful casts; reset on world/spec transitions. No unbounded cast history or arbitrary timer tables.
- Weaving: use actual readable melee/ranged spell range and recent readable Auto Shot events to advise entry after a shot; prioritize ready melee skills in melee, then retreat. Movement advisory only, not autopilot or exact swing cancellation logic. If range/swing evidence is unavailable, show an explicit manual weave cue instead of inventing a window. Respect casts/channels and disable melee instruction in BM/MM. Melee dwell capped to prevent sticky instructions; unknown range cancels phase. Both melee/ranged false means reposition (dead zone OR beyond range), not unknown; never prescribe a direction from both-false alone. Traps only on opt-in and verified melee range.
- Missing API or inaccessible states show actionable status and fail closed per feature; no per-frame chat spam. /hcf status reports availability flags and profile without secret numbers or private identifiers.

## Rotation evidence

MM search already completed: 1628 candidate/scenario evaluations, finalists 2000 iterations on independent seeds. Tested configurations are 60-level approximations using a current equipment snapshot, not level-59 live measurements or a proof of global optimum. Complete data stays local outside public repository; public research summary contains anonymized conditions and limitations only.

BM and SV weaving additional simulations compare upstream profiles, skill flags/mana thresholds, short/long/solo/raid/full-consume scenarios; SV compares 12/13.19/16-yard sim distances and 150/300-ms reaction. Final decisions will be documented with measured results. Simulation exact state is not available to addon; do not claim package reproduces simulator DPS or all decision branches. Sim distances use simulator reach conventions, never presented as exact in-game yards.

Known candidate structure: BM maintain sting/mark with confirmed evidence, Hawk/Hawk/Arcane cycle and Aimed fillers, separate Bestial Wrath/Rapid Fire advice; conserve prunes expensive fillers. MM adapts optional Aimed/Sniper usage to resource strategy. SV ranged instants after autos, melee Raptor/Mongoose/Strider, optional trap, retreat; safe manual cues when exact swing timing is unavailable. 3+ targets use Multi-Shot/Volley and permitted melee Explosive Trap; do not clip channel. All logic must honor available talents and ranks, not just nominal spec.

## Validation and release

Pure Lua decision/state functions have offline tests pinned to lupa.lua51 (verified _VERSION=Lua 5.1), including a Lua-5.1 syntax compile gate: all 3 profiles, short/long style modes, single/AOE, low mana/unknown mana, unknown readiness/range/movement, GCD, casts/channels, learned ranks, cast target changes, missed/resisted unknown aura, locale-independent IDs, profile resets, hunter-only client check, SV stale shot/dwell/phase boundaries, and no protected casting APIs.

UI adapter exercised with mock WoW API; All runtime API and event reads are confined to one adapter and passed through its guard before any use; static tests reject raw game APIs in decision/UI modules and audit raw result handling in the adapter. Secret sentinels catch indexing/arithmetic/conversion, but cannot intercept Lua boolean tests or mixed-type equality, so do not claim they prove full secret safety. Explicit tests return secret booleans through the guard and verify unknown output. Frame and /hcf status must explicitly report readiness unavailable rather than showing a usable next skill when every usable result is secret. Tests are offline, no live-client validation claimed. Package validation compiles every Lua file, checks TOC entries and dependency absence, ZIP top-level directory/member equality, version and SHA256. Full packaged source, tests, release notes and package manifest are in final Claude snapshot; binary ZIP is represented by exact textual member hashes and verified equality, not omitted from review scope.
